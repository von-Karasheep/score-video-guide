# Dvořák VII: production and archive lessons

Use this case before continuing the Dvořák set or starting a similar multi-movement guide. It records demonstrated failures and fixes from the complete 2026-11-10/11 production. The portable quality floor is in [production policy](production-policy.md); the first movement's two screenshot rounds are in [feedback rounds](dvorak-feedback-rounds.md). Do not repeat their full checklists here or treat historical timing as precision ground truth.

## What was actually delivered

Bychkov / Berliner Philharmoniker, 2021-03-11, official event DCH 53133. Four complete guides: I 627 s, II 552 s, III 452 s, IV 582 s; 3840×2160, 30 fps. Selected FLAC 48 kHz / 24-bit stereo samples and declared title/end silence were preserved in ALAC, with complete output decode and PCM equality checks. Practical measure maps and selected encoded-frame reviews were retained; there was no new claim of full-film note-by-note listening or frame-perfect synchronization. Theses, program notes and score observations remain distinct in each source ledger.

All four deliveries, standalone engineering and shared originals completed readback/upload checks. The earlier 2026-11-10 archive timeout was subsequently resolved; it is historical, not the current completion state. Upload means the macOS File Provider reported uploaded with no conflict; an independent server download/hash was not performed. A second redundant full reconstruction encode was not run merely to certify the rebuild script.

## Failure, remedy, prevention

| Observed problem | Applied remedy | Next-production check |
|---|---|---|
| The skill/archive root changed and was mistakenly used as the movie destination. Four movements were then scattered at the delivery root. | The 2026-11-11 Dvořák reorganization put four movement subfolders and their index in one work folder. | Follow the [current OneDrive delivery rule](production-policy.md#current-future-delivery-rule-onedrive-2026-11-11) for new work. Put the movement files side by side in the work's final directory. Resolve the destination from the delivery configuration. |
| Disk exhaustion interrupted downloads, export and verification; a nominal 4 GB did not cover every stage. | Use persistent local production, download only required video ranges where supported, and export/upload/verify/clean one movement before the next. Remove verified duplicates and regenerable analysis/JIT environments only after preserving selected results and versions. | Budget sources, frozen rebuild inputs, output, temporary mux/copy and operating headroom together. Measure current space at the stage boundary. A project-specific successful 1.2 GiB guard is not a universal minimum. On real insufficiency, preserve work and report the resource remedy. |
| A cloud pathname existed but the content was evicted or its read timed out. Re-reading a previously verified large source initiated needless hydration. | Distinguish directory existence, readable local bytes, recorded content hashes and provider upload status. Retain the completed readback evidence and query only pending uploads. | Stage required production inputs locally once. Do not rehydrate unchanged multi-gigabyte archives during a metadata-only reorganization. Same-volume rename can retain identity/size plus prior hash evidence; changed or uncertain content still needs readback. No GUI/application control is authorized for this user's archive workflow. |
| Large files finished before hundreds of small companion files; an uploaded movie alone did not establish complete delivery. | Wait for remaining covers, source records and engineering; retain per-file status and distinguish provider confirmation from an independent remote hash. | Check the complete required inventory, including final index and reports. Normal queued/uploading progress is not a reason to rerender or repeatedly rewrite files. Poll at bounded intervals, retain passed results, and report actual errors or a sustained stall with a concrete remedy. |
| The supplied upload's picture was unsuitable, while another same-event upload had clean pictures. | Use the selected lossless FLAC and watermark-free pictures from the verified same event. Exact-event descriptions/official information establish identity; a few landmarks establish edit offsets. | Check event identity and both codecs before committing. Do not substitute another performance, conceal a watermark with cropping, or call upconverted AAC a lossless source. The adopted +4.78 s audio/video offset belongs only to these sources and must not become a template default. |
| Domestic downloads could inherit Clash Verge settings; disabling an environment variable alone was insufficient evidence. | Explicitly disable downloader proxies, clear proxy variables for child processes, and record the real API/CDN route. This run's observed direct interface was en0. | Follow the mandatory routing policy for every redirected mainland media endpoint. Interface names vary by machine. If direct access cannot be verified, report and wait; do not fall back to Clash/Mihomo or silently change system settings. |
| Automatic alignment compressed a slow ending and sustained notes; printed spacing did not represent performance time. | Use maintained DTW as a candidate, then adopt actual measure landmarks and local corrections, including final reattacks, rests and decay. Keep a measure-linear cursor and freeze the accepted map. | Check opening, thematic boundaries, tempo changes, page route and ending before full export. Do not spread missing seconds evenly over the ending, demand unnecessary note precision, or reopen accepted timing for a visual-only fix. |
| Generic mood/orchestration text omitted the thematic and tonal argument. | Combine the score with actually read work-specific analysis, then state tonal status and concrete bass/chord/signature evidence in each bounded panel. | Identify the real thematic opposition, transformed return and ending. In IV, the secondary group moves A major → D major, the march is deferred to the coda, and stable final D major begins only at m431, not at the whole m425 maestoso. These are score-specific conclusions, not a universal sonata recipe. |
| A fixed staff count mislabelled divided pages and other movements; pickup conventions could shift all measure numbers. | Use page-specific visible staff geometry and explicit measure conventions. III normally has 13 rows, divided flute/cello pages 14; IV normally has 15, divided flute pages 16 in this edition. | Inspect movement opening, first divided page and each motif's actual staff. Check MIDI/score pickup conventions; never apply a blanket +1 from another analyst's numbering. Do not transpose already concert-pitch symbolic data again. |
| MiSans lacked musical accidental glyphs even though the text and render were valid. The initial II export therefore needed correction. | Bundle DejaVu Sans as a verified notation-symbol fallback with its license, and make both raster text and ASS subtitles see it. | Test actual glyph coverage for ♭, ♯ and ♮ before full export, then inspect the encoded tonal panel and callout. A font name or successful encoder exit is not a visibility test. |
| Motif crops cut expression text, or global padding admitted fragments of the neighboring staff. | Use page/staff-specific bounds; preserve notes, ledger lines, legato/Solo/espressivo and relevant articulations. | Inspect an opening crop and a crowded/changed-instrument crop. Match every explanation to the printed mark. Keep the selected phrase and its label meaningful; explicitly label a retained prototype rather than pretending it is sounding. |
| Earlier revisions lost theme chips, score marks, module boundaries and caption spacing; featured names were not resolved. | Apply the accepted blue/brown theme identity across header, real score outline, motif and timeline; keep one left page caption, bounded tonal/motif panels and a clear PiP-caption gap. Reuse user-confirmed Mayer only for the relevant shots; retain the instrument-only clarinet caption after the user's waiver. | Compare actual composed frames with the accepted reference, including a long caption and dense tonal text. Seek written same-event credits within a bounded search; do not identify faces, infer historical seats from current rosters, or ask again for an already waived name. |
| Old absolute paths, a removed analysis environment, or missing dependencies could make an archived project unusable. | Preserve relative frozen background/PiP/audio/ASS/fonts/encoder inputs, exact command, hashes, editable score/analysis and a standard-Python rebuild script. Normalize numeric subprocess arguments to strings at the execution boundary. | The rebuild must not read the finished film or depend on an old Movies path or the analysis virtual environment. Preserve source/version records before cleaning environments. Verify input closure and actual command compatibility; report whether a separate reconstruction encode was performed. |

## Historical project organization and maintenance

Read `score-video-paths.json` for this historical Dvořák project. Its recorded `work_delivery_root` is the `德沃夏克第七交响曲_Bychkov20210311` child of `音乐会预习/预习视频/最终成片`. The work folder holds the movement folders, delivery index, retrospective and engineering links. The frozen rebuild uses relative inputs. New deliveries use the separate OneDrive configuration.

The shared `制作脚本` directory records production history and may contain old configured absolute paths. It is not the standalone rebuild entrypoint. Read current configuration before adapting those scripts; do not blindly rerun historical delivery scripts. The movement-level `重建成片.py` uses relative inputs and is the portable film-rebuild entrypoint.

Before the next full encode, freeze a small composed-frame check covering an A phrase, a B phrase, a return, a divided-staff page, accidental glyphs, a long caption and the ending. Reuse a successful workflow. If the required practical standard cannot be met with current data or resources, state what exists, the obstacle, remedy and feasibility, then wait as required by production policy. Routine progress and integrity checks are distinct from speculative repeated tests.

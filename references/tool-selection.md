# Reuse-first tool selection

Audit date: 2026-11-10. This is a routing guide, not a claim that every listed tool has passed this production workflow. Read it before implementing a new stage. Follow the immediate assess/report/wait rule in production-policy.md; no 30-minute trial allowance applies to this workflow. Do not install every candidate or rerender previous films merely to maintain the skill.

## Findings from the actual Barber project

The project used custom `band_dtw` and `optical_dtw.cpp` alignment kernels and project-specific geometry/label code. They may have legitimate performance or input-specific reasons, but future work must establish a standard-library baseline before writing a replacement. The tested environment already exposes librosa, mido and pretty_midi. An import-availability probe in `/private/tmp/barber-compare-env/bin/python` did not find partitura, parangonar, verovio, scenedetect, pymupdf or music21. This is one environment, not proof they are absent everywhere. No MuseScore, Sonic Visualiser or Audacity bundle was found by the limited top-level `/Applications` name scan. Check again when needed.

Audiveris, HOMR, Basic Pitch, FFmpeg and Pillow were already used; do not report them as newly discovered replacements or rerun their failed pilots without changed evidence. Chinese labels were visually checked because raw OCR made errors; OCR can reduce candidate-entry work but cannot replace that verification. The musical map remains a candidate, despite completed technical export checks.

## Preferred routes and acceptance tests

| Stage | Reuse first | What it saves / boundary | First test before full use |
|---|---|---|---|
| Downloads | Installed `bilibili-video-download` skill / yutto | Reuse authentication/download workflow, not new scraping code. Already available. | Verify the exact BV/source identity and obtainable audio codec. |
| Score PDF access/crops | Installed `pdf:pdf` skill, Poppler/PDF tools | Reuse page rendering and text extraction. Native PDF text may supply instrument labels; scanned pages need OMR/OCR. | Render one dense page; preserve printed edition and coordinates. |
| MusicXML/MIDI parsing | [Partitura](https://github.com/CPJKU/partitura) | Reuse score/performance representation and note-array interfaces instead of hand-parsing all MusicXML semantics. Documentation checked; not tested here. | Test a pickup, repeat, transposition, tie and tuplet against the original score; preserve occurrence IDs. |
| Symbolic score correction/export | [MuseScore command-line export](https://musescore.org/en/print/book/export/html/278640) | Existing notation editor/exporter can inspect corrected XML and produce MIDI/PDF; not an OMR engine. Linked command reference may describe an older version; verify local-version options. Not tested here. | Round-trip one corrected passage, checking duration, voices, transposition and layout. Do not silently replace the accepted scan edition with a new engraving. |
| Candidate alignment | [librosa DTW](https://librosa.org/doc/main/generated/librosa.sequence.dtw.html) | Existing DTW/backtracking, custom step sets and constraints before a new C++ kernel. Import available; this audit did not benchmark it. | Same features on a short reference/target pair; check known landmarks, path direction, repeats, memory and time. Dense matrices may be unsuitable for full long works: measure first, then document why a banded implementation is needed. |
| Symbolic performance alignment | [Parangonar](https://github.com/sildater/parangonar) | Existing alignment/synchronization package to investigate for compatible symbolic inputs; do not assume arbitrary orchestral-audio support. Documentation checked, untested. | Select its documented method for actual input types; compare held-out note identities and timing. No raw-transcription accuracy is implied. |
| Real-time score following | [Matchmaker](https://github.com/pymatchmaker/matchmaker) | Online score-following framework, not the default replacement for offline full-film alignment and not OMR. Documentation checked, untested. | Use only if online following or a justified comparator is needed; test recovery after a missed event. |
| Digital score geometry | [Verovio toolkit](https://book.verovio.org/toolkit-reference/toolkit-methods.html) | SVG element IDs, element lookup and timemap APIs reduce manual note-box work when a matching symbolic score is available. Documented, untested here. | Check imported notation and SVG element positions against the accepted score; map nominal toolkit time through performance alignment. It does not locate notes on an arbitrary scanned page or supply recording timing. |
| Staff-name/technique text candidates | [Tesseract TSV/hOCR](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage.html) or existing PDF text extraction | Obtain text boxes and confidence rather than manually typing every label. OCR is for printed words/abbreviations, not recognition of musical glyph semantics. Documentation checked; not a proven replacement for Barber's manual label checks. | Compare full, reduced and divisi pages; normalize abbreviations with a checked dictionary and verify each row. Fall back to original left-margin review for ambiguous names. |
| Shot boundaries/contact sheets | [PySceneDetect](https://www.scenedetect.com/docs/latest/) | Existing scene detection and representative-frame export before writing cut-detection code. Documented, untested here. | Test fast cuts, fades and a pan; inspect false/missed cuts. Instrument/person labels still require visual evidence. Do not infer a new person from every detected cut. |
| Audio inspection and annotations | [Sonic Visualiser](https://www.sonicvisualiser.org/), its linked Vamp plugins / Sonic Annotator | Existing waveform, spectrogram and annotation UI; batch feature extraction via Sonic Annotator. Documentation checked, untested here. | Open one known passage and export timestamps with declared source clock. Choose a plugin's documented task; monophonic pitch/beat estimates are not orchestral truth. A GUI does not create listening capability for an agent that cannot hear. |
| Research/references | Installed `paper-lookup`, `citation-management`, `concert-preview-notes` skills | Reuse literature discovery, metadata checks and established analysis-note workflow instead of new bibliographic fetchers. | Verify published DOI/publisher and actual reading scope. Reused prose requires recording/version compatibility. |
| Composition/validation | Existing FFmpeg pipeline, ffprobe and libass; `export-delegation: sol` | These were already used. Retain finite streaming inputs, local verified caches and independent PCM checks; avoid rewriting the compositor for each work. | Short representative 4K test, then full decode, encoded-frame checks and delivery readback. Lead freezes musical/layout data before GPT-6.1 Sol exports. |

The no-MIDI OMR/Basic Pitch comparison routes remain in [recovery and display checks](recovery-and-display-checks.md). Do not mistake two skills invoking one engine for independent validation. Do not install commercial tools, register accounts or buy subscriptions merely because they appear in a search result.

## Selection procedure for the next agent

1. Inventory existing project outputs, skills, applications and the actual Python environment. Reuse identity-matched successful outputs rather than recomputing them.
2. Select only the tools relevant to the missing stage. Prefer existing installed skills; consult official docs for API/version/input limits. Record upstream version or commit when adopting an implementation.
3. Only when needed to answer a feasibility question, define one small representative fixture and success criterion BEFORE running a pilot. Compare against real score/recording evidence and the existing baseline; retain correctness, runtime, peak memory and failure cases. A package importing successfully is not a successful pilot. If the result exposes a blocker to the practical floor, report and wait rather than cycling through the candidate list.
4. Use the standard tool if it passes. Add only a thin configuration/format adapter. A custom engine requires a documented unsupported capability or measured failure/performance constraint, not preference for writing code. Do not port a whole external package into this skill.
5. Save a project `tool-decisions.json` with stage, input hashes, candidate URL/version, installed environment, test fixture, outcome/evidence, chosen route and reason. Mark documentation-only entries untested. Maintain one selected implementation per stage where practical; remove obsolete adapters only after checking callers.
6. Keep task-specific work: source edition identity, musical analysis, motif interpretation, Chinese wording, scan-specific geometry and difficult timing review. No searched plugin establishes those automatically. Frozen data remains the source of truth for section colors, staff labels, callout geometry and output edits.

## Coverage limits

This maintenance audit verified official documentation and a limited local inventory; it did not install or execute the new candidates, benchmark speedups, or certify increased musical accuracy. The guide supplies next-run pilot routes, not a promised universal automated pipeline. Existing tested project adapters remain usable until a replacement passes its actual task.
